| 2026-09-24 | AN-1 | Deleting an entry always leaves a hidden `PENDING_DELETE` tombstone, even for a create the server never confirmed. | The server may already have it (a sync whose answer was lost). | 2026-09-24 | AN-1 | `SyncWorker` is unique work `entry-sync` with `ExistingWorkPolicy.REPLACE`, `NetworkType.CONNECTED`, and 30 s exponential backoff. | A new change restarts a waiting or running sync right away instead of waiting out a backoff. This is safe because every sync item is idempotent on the server and results are applied in a transaction. |
| 2026-09-24 | AN-1 | Whole-request results: network, 5xx, 408, 429, unexpected JSON, and `ACCOUNT_NOT_FOUND` → retry with backoff. `UNAUTHENTICATED` and other 4xx → stop until the next trigger (app start, sign-in, or a new change). The outbox is never dropped. | A timer retry can't fix a signed-out user or a refused request. |
| 2026-09-24 | AN-1 | Per-item `INVALID`, `INVALID_TIMESTAMP`, or `CONFLICT` keeps the row and stores the server's message in `lastError` ("Couldn't sync"). The row leaves the outbox (`EntryDao.getOutbox`) until the user edits or deletes it. `ERROR`, unknown statuses, and missing results are retried. | Final errors must not be retried forever, and nothing is silently lost. Known limit: a failed entry in a closed week can't be edited or deleted locally, so it stays "Couldn't sync" (e.g. offline for more than 14 days). |
| 2026-09-24 | AN-1 | A `WEEK_CLOSED` answer reverts the local row to the server copy (or restores a deleted row) and adds to a persisted count (`SyncNotices`, SharedPreferences `menosan_sync`). The Audit tab shows "A change couldn't be saved" until it's dismissed. | The sync may run in the background, so a one-shot in-memory message could be lost. Only a count is stored, never contents. |
| 2026-09-24 | AN-1 | Results are applied only to rows the user hasn't changed since they were sent. A newer change is sent in the next pass of the same run (up to 3 passes). | Never overwrite an edit or delete made while a request was in flight. |
| 2026-09-24 | AN-1 | The current-week merge (`GET /v1/entries`) runs on app start, after sign-in, when the device comes back online (all while signed in), and when the Audit tab opens. The server wins for synced rows, local wins for pending rows, and synced rows the server no longer has are removed. It shares a mutex with the push. | Plan §10 AN-1. The mutex stops a merge from deleting a row the push just confirmed. |
